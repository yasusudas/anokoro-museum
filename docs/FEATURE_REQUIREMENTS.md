# 機能要件（Feature Requirements）

[PRD.md](./PRD.md) を実装可能な単位へ分解した仕様。各機能は「前提・振る舞い・完了条件・例外」を満たして初めて完了とする。

## 機能一覧

| ID | 機能 | 優先度 | 状態 |

| F-01 | 生まれ年設定 | Must | UIのみ |

## F-01: 生まれ年設定

**概要:** 来場者が4桁の生まれ年を設定し、関連する展示を受け取る。

- 前提: 初回訪問または設定変更時
- 振る舞い: 許容範囲内の年を選択できる。ログイン前は端末、ログイン後はプロフィールへ保存する
- 完了条件: 選択年がUIへ反映され、関連展示が更新される
- 例外: 未入力・範囲外では保存せず、理由を表示する
- ルール: 年代条件は「その展示に親しんだ可能性」の目安であり、閲覧を禁止する条件には使わない

## F-02: 展示回廊・絞り込み

**概要:** 展示を博物館の回廊として横方向に閲覧する。

- 前提: 公開済み展示が1件以上ある
- 振る舞い: ホイール、トラックパッド、左右キー、画面内ボタンで移動できる。年代・カテゴリで絞り込める
- 完了条件: 条件に一致する公開展示だけが表示され、展示を選択できる
- 例外: 0件なら条件を解除できる空状態を表示する。取得失敗なら再試行を提示する
- ルール: 縦方向へページ全体をスクロールさせない。`prefers-reduced-motion` では強い移動演出を抑える

## F-03: 展示詳細

**概要:** 展示名、説明、画像、カテゴリ、関連年代、共感数、スレッド入口を表示する。

- 前提: 対象が公開済み、または投稿者・運営がプレビュー権限を持つ
- 完了条件: URLから直接開け、再読み込みしても同じ展示を表示できる
- 例外: 存在しない・非公開・削除済みの場合は404相当を表示する
- ルール: 画像には代替テキストと出典情報を持たせる

## F-04: 認証

**概要:** メールまたはOAuthで登録・ログイン・ログアウトする。

- 完了条件: セッションが安全に維持され、保護操作では未認証ユーザーをログインへ案内する
- 例外: 認証失敗の内部情報を露出せず、再試行可能な文言を表示する
- ルール: 公開展示の閲覧はログイン不要。投稿、コメント、しんみりはログイン必須

## F-05: しんみり

**概要:** 登録ユーザーが展示へ一度だけ静かな共感を付けられる。

- 前提: ログイン済み
- 振る舞い: 付与と解除をトグルでき、件数へ即時反映する
- 完了条件: 再読み込み後も状態が保持される
- 例外: 保存失敗時は表示を元に戻して通知する
- ルール: `(exhibit_id, profile_id)` を一意にし、連打で重複させない

## F-06: コメントスレッド

**概要:** 展示にまつわるエピソードを閲覧・投稿する。

- 前提: 閲覧は公開展示、投稿はログイン済み
- 完了条件: 新しいコメントが保存され、投稿者と投稿時刻とともに表示される
- 例外: 空白、上限超過、不適切判定、通信失敗では保存しない
- ルール: 最大500文字。編集履歴はMVP外。本人削除は論理削除し、運営も非表示化できる

## F-07: 展示候補の投稿

**概要:** 登録ユーザーが展示候補を画像・説明・年代とともに送る。

- 必須項目: 名前、説明、カテゴリ、関連開始年、関連終了年、画像、画像出典・権利確認
- 完了条件: `pending` 状態で保存され、投稿者が審査状況を確認できる
- 例外: 画像形式・容量・入力値が不正ならアップロードを確定しない
- ルール: 投稿直後に一般公開しない

## F-08: 展示審査

**概要:** 運営が候補を承認、差し戻し、却下、非公開化する。

- 前提: 運営権限を持つ
- 完了条件: 状態変更、実行者、時刻、理由が記録される
- ルール: 一般ユーザーは審査API・未公開一覧へアクセスできない。公開後も権利問題があれば非公開にできる

## F-09: 並び替え

**概要:** 新着、しんみり順、年代との関連度で展示を並び替える。

- 完了条件: 選択中の条件がURLへ反映され、共有・再読み込みで維持される
- ルール: 既定は年代との関連度と運営設定順を組み合わせる。件数だけで露出を固定しない
