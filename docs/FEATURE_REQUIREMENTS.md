# 機能要件（Feature Requirements）

[PRD.md](./PRD.md) を実装可能な単位へ分解した仕様。各機能は「前提・振る舞い・完了条件・例外」を満たして初めて完了とする。

## 機能一覧

| ID | 機能 | 優先度 | 状態 |
| --- | --- | --- | --- |
| F-01 | 生まれ年設定 | Must | UIのみ |
| F-02 | 展示回廊・絞り込み | Must | Prototype |
| F-03 | 展示詳細 | Must | Prototype |
| F-04 | 認証 | Must | 実装済み（実DB検証待ち） |
| F-05 | しんみり | Must | UIのみ |
| F-06 | コメントスレッド | Must | 実装済み（展示UUID接続・実DB検証待ち） |
| F-07 | 展示候補の投稿 | Must | 未実装 |
| F-08 | 展示審査 | — | スコープ外 |
| F-09 | 並び替え | Should | 未実装 |

## F-01: 生まれ年設定

**概要:** 来場者が4桁の生まれ年を設定し、関連する展示を受け取る。

- 前提: 初回訪問または設定変更時
- 振る舞い: 1900年から日本時間の現在年までの範囲で選択できる。端末に保存し、DBでは管理しない
- 完了条件: 選択年がUIへ反映され、関連展示が更新される
- 例外: 未入力・範囲外では保存せず、理由を表示する
- ルール: 展示側は対象来場者の生まれ年レンジを持ち、設定した生まれ年がその範囲に含まれるかで関連づける
- ルール: 年代条件は「その展示に親しんだ可能性」の目安であり、閲覧を禁止する条件には使わない
- ルール: 生まれ年はDBへ保存しないため、端末を変えると復元されない

## F-02: 展示回廊・絞り込み

**概要:** 展示を博物館の回廊として横方向に閲覧する。

- 前提: 公開済み展示が1件以上ある
- 振る舞い: ホイール、トラックパッド、左右キー、画面内ボタンで移動できる。年代・カテゴリで絞り込める
- 完了条件: 条件に一致する公開展示だけが表示され、展示を選択できる
- 例外: 0件なら条件を解除できる空状態を表示する。取得失敗なら再試行を提示する
- ルール: 縦方向へページ全体をスクロールさせない。`prefers-reduced-motion` では強い移動演出を抑える

## F-03: 展示詳細

**概要:** 展示名、説明、画像、カテゴリ、関連年代、共感数、スレッド入口を表示する。

- 前提: 対象の展示が存在する
- 完了条件: URLから直接開け、再読み込みしても同じ展示を表示できる
- 例外: 存在しない・削除済みの場合は404相当を表示する
- ルール: 画像には代替テキストを持たせる

## F-04: 認証

**概要:** メールまたはOAuthで登録・ログイン・ログアウトする。

- 完了条件: セッションが安全に維持され、保護操作では未認証ユーザーをログインへ案内する
- 例外: 認証失敗の内部情報を露出せず、再試行可能な文言を表示する
- ルール: 公開展示・コメント・各いいねの閲覧はログイン不要。展示投稿、コメント投稿・削除、しんみり、コメントいいねの付与・解除はログイン必須

## F-05: しんみり

**概要:** 登録ユーザーが展示へ一度だけ静かな共感を付けられる。

- 前提: ログイン済み
- 振る舞い: 付与と解除をトグルでき、件数へ即時反映する
- 完了条件: 再読み込み後も状態が保持される
- 例外: 保存失敗時は表示を元に戻して通知する
- ルール: `(item_id, user_id)` を一意にし、連打で重複させない

## F-06: コメントスレッド

**概要:** 展示にまつわるエピソードを閲覧・投稿する。

**MVP:**

- コメント閲覧
- ログインユーザーのコメント投稿
- 本人のコメント物理削除
- コメントへのいいね付与・解除と件数表示
- 運営によるコメント非表示は持たない（F-08参照）

- 前提: 閲覧は公開展示、投稿・削除・いいね付与はログイン済み
- 完了条件: 新しいコメントが保存され、投稿者と投稿時刻、いいね件数とともに表示される
- 例外: 空白、上限超過、通信失敗では保存しない
- ルール: 前後の空白を除いて1〜500文字。本文中の改行（連続する空行を含む）は保持する。HTML・Markdownは解釈せず、HTTP/HTTPS URLだけを安全にリンク化する。編集履歴は持たない。本人削除は物理削除する。いいねは `(comment_id, user_id)` を一意にする
- ルール: 一覧は新着順。未認証時は一覧とログイン導線を表示し、`/login?next=/exhibits/{exhibit_id}` から復帰できる。投稿中は二重送信を防ぎ、失敗時は入力を保持する
- ルール: 入力中の本文は展示・ユーザーごとに端末へ下書き保存する。オフライン時は送信せず下書きを保持し、復帰後に送信できる

## F-07: 展示候補の投稿

**概要:** 登録ユーザーが展示候補を画像・説明・年代とともに送る。

- 必須項目: 名前、説明、カテゴリ、画像、画像の代替テキスト、対象生まれ年（開始・終了）。画像の権利確認も必須
- 完了条件: 保存と同時に公開され、回廊と詳細から閲覧できる
- 例外: 画像形式・容量・入力値が不正なら保存しない
- ルール: 審査を行わないため投稿は即時公開される。画像のアップロード、代替テキスト、投稿者による著作権・商標・肖像権の確認がすべて完了してから展示を保存・公開する。未確認の画像や代替テキストのない画像は保存しない

## F-08: 展示審査（スコープ外）

サークル内ハッカソン用途のため、運営ロールと展示審査を持たない。展示候補（F-07）は投稿と同時に公開される。

この判断により、以下が成立しない。不特定多数へ公開する場合は再検討する。

- 不適切な展示・コメントを運営が非公開化する手段
- 公開後に権利問題が判明した際の取り下げ
- 展示の公開状態（`status`）と審査履歴の記録

## F-09: 並び替え

**概要:** 新着、しんみり順、年代との関連度で展示を並び替える。

- 完了条件: 選択中の条件がURLへ反映され、共有・再読み込みで維持される
- ルール: 既定は年代との関連度を用いる。件数だけで露出を固定しない
